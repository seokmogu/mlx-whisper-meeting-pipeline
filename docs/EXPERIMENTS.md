# 실험 로그 — 모델·기법 선택 근거

기간: 2026-07-07 ~ 07-13. 회의록 파이프라인의 각 단계(전처리 → ASR → 화자분리 → 이름/용어 교정 → 노트 생성)에 대해 대안을 실측 비교하고 채택/기각을 결정한 기록. 재검토·재논의를 막기 위한 근거 문서다.

## 핵심 결론 (한 줄)

전사 코어(Demucs → mlx-whisper large-v3 → pyannote community-1)는 로컬·무료·프라이버시 모두에서 최선이라 **유지**하고, 개선은 **사후 교정 레이어(누적 확정 사전 + 자모 음성유사도)**에 집중했다. 이름 오인식은 어떤 ASR로도 못 고친다(오디오 애매성)는 것을 로컬/클라우드 4종 ASR로 확정했다.

## 반복 확인된 원리

**이름 오류(예: "성모"=구석모, "병사"=고병삼)는 ASR 정확도 문제가 아니라 오디오 자체의 애매성이다.** 화자가 별칭/약칭으로 부르거나 발음이 흐리면, whisper·Qwen·OpenAI·GCP 4개 엔진 모두 똑같이 잘못 듣는다. 따라서 ASR 교체로는 해결 불가이며, **문맥을 아는 사후 교정(ledger + 자모 + 노트 LLM)만이 해법이다.**

---

## A. 화자분리 — `num_speakers=2` 고정 → `min/max` 범위 (채택)

- **문제**: 기존 `DIARIZATION_NUM_SPEAKERS=2` 고정. 거의 모든 회의록이 "A/B 2인 분리지만 실제 다인 회의"라고 경고.
- **방법**: 실제 회의 3건(89분 CFO, 62분 AX Weekly, 31분 PD×Nika)에서 고정2 vs 범위(min2/max5) vs 무제한 비교.
- **결과**: 고정2는 3인+ 발화를 2명으로 뭉갬(예: CFO 회의의 3분43초 구간이 한 화자 "A"로 붕괴 — 실제론 부채→지표→클라우드로 화제가 바뀌는 다인 대화). 무제한(2~8)은 반대로 한 사람의 연속 발화를 여러 명으로 과분할. **2~5 범위가 최적**(과분할 없이 다인 복원).
- **결정**: `DIARIZATION_MIN_SPEAKERS=2`, `DIARIZATION_MAX_SPEAKERS=5`. pyannote 내부는 WeSpeaker ResNet34 임베딩 + VBx(GMM) 클러스터링 — 인원수 힌트 없으면 과/과소분할이 일반적 실패 모드라 범위 힌트가 정답.

## B. 음성 전처리 — DeepFilterNet3 (기각, Demucs 유지)

- **방법**: 노이즈 심한 6분 구간을 Demucs+afftdn(현재) vs DeepFilterNet3(mlx-community) vs 무처리로 전사 비교.
- **결과**: DeepFilterNet3가 **오히려 악화** — 부정어 누락(제품방향이 "아니"라서 → "이라서"로 의미 반전) + 환각 반복 루프("싫어해 싫어해 싫어해") 유발. Demucs+가드 경로가 반복률 6.2%로 최청정.
- **결정**: **Demucs 유지.** 2026 연구("When Denoising Hinders")대로 강한 denoiser가 WER을 되레 높일 수 있음을 실측 확인.

## C. ASR 환각 억제 파라미터 (채택)

- **문제**: 전화 끊김/침묵/크로스토크 구간에서 "하면 하면", "음 음 음" 반복 환각. 한 회의는 78분 중 46분이 이 노이즈로 소실.
- **방법**: mlx-whisper의 `hallucination_silence_threshold` 등이 소스에 있으나 기본값(None=꺼짐)으로 방치돼 있었음. 명시 설정 + Demucs 경로에서 검증.
- **결정**: `hallucination_silence_threshold=1.5`, `no_speech_threshold=0.6` 등 명시. (별도 모델 불필요 — 이미 있는 안전장치를 켠 것.)

## D. Identity Ledger — 누적 확정 표기 사전 (신설, 핵심)

- **근본 원인**: 확정된 이름("성모→구석모")이 다음 회의로 전달 안 돼, 15번 회의에서 15번 처음부터 재추측.
- **구현**: 모든 노트의 `## 검증 완료`에서 `STT변형 → 정정` 매핑을 누적(`build_identity_ledger.py`), 노트 생성 프롬프트에 주입. 매 파이프라인 실행 시 재빌드 → 피드백 루프.
- **실측**: 기존 노트 32개 배치 재생성 시 검증완료 매핑 **평균 5개 → 16.8개** (3~4배).
- **후속 수정 2건**:
  - *count 인플레이션*: canonical별 합산이라 변형 많은 이름의 count가 부풀려짐(구석모 39회). → **변형별 회의 확정 횟수**로(성모 18회, 성문 9회, 성원 7회…).
  - *전사 grounding*: 노트가 주입된 사전을 그대로 따라 적은 매핑까지 누적되는 자기강화 방지 → 각 회의의 **전사에 실제 등장할 때만** 카운트. 문맥 유래 매핑 29개 걸러냄.

## E. wdc 내부 컨텍스트 — 관련회의 키워드 라벨 (Phase 1 채택 / 의미검색 보류)

- **Phase 1(채택)**: wdc `meeting_notes`(사내 2,580 회의)에서 transcript 주제로 관련 회의 검색 → **decision_labels·topics·mentions 라벨만** 주입(자유텍스트 결정문 제외 = 타팀 내용혼입 환각 방지). 제네릭 툴명 제외 + 제목매칭 가중으로 relevance 확보. 적대적 리뷰로 8개 결함(프롬프트 인젝션 방어, LIKE 이스케이프 등) 수정.
- **Phase 2(보류)**: wdc에 KURE-v1(한국어) 하이브리드 벡터검색이 구현돼 있음. 파일럿(macmini 임베딩 108ms/청크)은 성공했으나 — (1) 런타임 macmini SSH 의존성으로 파이프라인 취약화, (2) meeting_notes↔documents 매핑이 O(n×m)로 느림 → **보류.** 오프라인 사전계산 방식이 되면 재검토.

## F. 로스터 병합 (채택)

- 정적 스냅샷(familybab 566명) → wdc `notion_users.json`(매일 자동 갱신) 병합 → 629명. 이름 커버리지·신선도 향상, 이메일 등 PII 미노출.

## G. 자모 음성유사도 교정 (#1, 채택)

- **동기**: ledger는 **이미 확정된** 변형만 잡음. 처음 나오는 새 오인식은 못 잡음(콜드스타트).
- **구현**: 순수 유니코드 자모 분해(**의존성 0**) + 편집거리로, 전사의 이름 토큰을 로스터 630명과 발음유사 매칭 → 후보 힌트 주입(자동치환 아님). `phonetic_name_candidates.py`.
- **결과**: 성모→구석모, 병사→고병삼, 경성→이경석, 훈화→송훈화 등 ledger에 없던 후보를 결정론적으로 제시. LLM A/B에서 고병삼을 새로 해결. ledger 포화 회의에선 한계효용 작으나, 신규/희귀 이름 콜드스타트를 메움. 비용 0·오프스위치.

## H. ASR 모델 비교 — mlx-whisper large-v3 vs Qwen3-ASR-1.7B (whisper 유지)

- **방법**: 같은 5분 세그먼트를 두 모델로 실측 전사(mlx-qwen3-asr, 로컬).
- **결과**: 속도는 Qwen 1.5배(18초 vs 27초). 그러나 **영어 tech 용어에서 whisper 압승** — Qwen은 Ops→"업스", QA→"퀴어"로 음차. 이름은 무승부(둘 다 성모/병사). 낭독체 벤치마크(FLEURS-ko 2.57% vs 3.1%)는 Qwen 우세였으나 실제 회의에선 뒤집힘.
- **결정**: **whisper large-v3 유지.** ("벤치마크 ≠ 실제 회의" 실증.)

## I. 클라우드 유료 ASR 비교 — 로컬 vs OpenAI vs GCP (로컬 유지)

같은 5분 세그먼트(20260707) 4-way 실측:

| 엔진 | 위치 | 속도 | 영어 tech 용어 | 이름 | 비용 |
|---|---|---|---|---|---|
| **whisper large-v3** | 로컬 | 27초 | **7/7 ✅** | 못 잡음 | $0 |
| GCP Vertex Gemini 2.5 | 클라우드 | 20초 | 6/7 (SSOT✗)* | 못 잡음 | ~$0.001/분 |
| OpenAI gpt-4o-transcribe | 클라우드 | 18초 | 3/7 (QA→Q&A, Ops→옵스) | 못 잡음 | ~$0.006/분 |
| Qwen3-ASR 1.7B | 로컬 | 18초 | 0/2 핵심✗ | 못 잡음 | $0 |

\* GCP Gemini의 영어 선전은 "영어는 영어로" **프롬프트 지시(LLM instructability)** 덕분이지 raw ASR 실력이 아님 — 우리 노트-LLM이 이미 하는 일과 겹침.

- **핵심**: 유료 클라우드 둘 다 로컬 whisper를 못 이김. 영어는 로컬이 우세, 이름은 **4개 엔진 전부 못 고침**, 비용·프라이버시는 로컬 압도.
- **거버넌스**: 회의 오디오는 Confidential — 외부 전송은 엔터프라이즈 계약 하에서만. 실측 후 GCS 업로드분은 즉시 삭제.
- **결정**: **로컬 whisper 유지.**

## J. OpenRouter 검토 (기각)

- OpenRouter는 전용 ASR도 aggregates(Chirp 3, Azure MAI-Transcribe, Voxtral, Parakeet 등). 그러나 대부분 이미 테스트(OpenAI)/직접접근 있음(Chirp, GCP)/한국어 없음(Parakeet)/기각(turbo). 유일 미시험은 Azure MAI-Transcribe.
- **기각 이유**: (1) **외부 애그리게이터 = 거버넌스 다운그레이드**(직접 엔터프라이즈 계약보다 나쁨), (2) 이름 문제는 여전히 못 고침. 시험할 가치 있으면 OpenRouter 말고 직접 엔터프라이즈로.

## K. 파이프라인 견고성 (적대적 리뷰 → 수정)

15개 확정 결함 중 고가치·저위험 적용:
- 손상 오디오(ffprobe 실패)가 큐에 남아 전사를 무기한 정지 → 격리
- `push-notes.sh` push 실패 시 루프 중단·커밋 유실 → 분리·재시도
- ledger count 인플레이션·`후보` 헤지 미제거 (D 참조)
- `format_transcript.py` 화자 11명↑ StopIteration 크래시 → A~Z, S27… 무한
- `.env` 무가드 소싱 5개 → 우아한 처리
- identity 게이트 하드실패(노트 통째 폐기) → **비차단 경고**로 전환

## 최종 스택 (2026-07-13 기준)

```
Demucs(보컬분리) + ffmpeg EQ/denoise
  → mlx-whisper large-v3 (환각 가드 ON)
  → pyannote community-1 (min2/max5)
  → format_transcript
  → 노트 LLM (Claude/Codex, 클라우드) — 주입: 로스터 + 누적 확정 사전 + 자모 후보 + wdc 관련회의 라벨
```

전사·화자분리·교정은 100% 로컬(맥북). 노트 문장 생성만 클라우드 LLM(본질적). 클라우드 유료 ASR·대체 모델을 광범위 실측했으나 이 조합을 능가하지 못했다.
