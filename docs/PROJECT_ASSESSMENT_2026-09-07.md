# 프로젝트 평가 및 개선 — 2026-09-07

## 목표와 완료 기준

로컬 녹음에서 원문 전사, 검증된 회의록, 맥락 리뷰, 게시 검토용 파생본까지 이어지는 흐름을 평가한다. 재현 가능한 필수 결함은 기존 구현을 확장해 수정하고, 회귀 테스트와 격리된 통합 검증으로 결과를 확인한다.

- 원본 오디오와 확정 전사를 보존한다.
- 단계가 실패하면 실패를 드러내고, 재실행으로 미완료 작업을 복구한다.
- 전사·회의록·리뷰가 준비된 회의만 별도 게시 검토 큐로 전달한다.
- 로컬 실행은 Notion 쓰기를 하지 않는다.
- 수정한 동작의 회귀 테스트, 기존 테스트, 셸 문법 검사 및 diff 검사를 통과한다.
- 평가 결과, 변경 근거, 검증 범위와 남은 한계를 이 문서에 기록한다.

실제 회의 재처리, Notion 게시, 외부 배포, 스케줄러 변경, 자격증명 변경, 커밋·푸시는 이번 범위에 포함하지 않는다.

## 실행 계획

1. **기준선 확인**: 프로젝트 계약과 진입점, 기존 테스트, 비식별 운영 메타데이터를 확인한다.
2. **독립 진단**: 오디오 수집·전사 보존, 로컬 단계 복구, 게시 준비·결과 검증을 나눠 조사한다.
3. **재현 후 수정**: 영향이 큰 결함을 합성 데이터와 임시 디렉터리로 재현하고 최소 변경을 적용한다.
4. **통합 검증**: 수정 영역이 합쳐진 상태에서 전체 기존 테스트와 새 회귀 테스트를 실행한다.
5. **종료 판단**: 필수 로컬 결함 해결 여부와 직접 실행하지 않은 외부 의존성 검증을 구분한다.

## 평가 및 검증 기록

**판정: 핵심 처리 기능은 구현되어 있었으나, 실패 복구와 게시 준비·성공 판단이 문서상 계약에 미달했다. 재현한 결함을 수정했고 로컬 검증을 완료했다. 실제 음성 인식 정확도와 외부 연결 E2E는 별도 검증이 필요하다.**

이번 평가의 우선순위는 녹음 누락·부분 산출물·실패의 성공 오인·승인되지 않은 게시 방지였다. 기능을 추가로 넓히거나 모델을 교체하지 않았다.

### 기준선

- 시작 시 Git 작업 트리는 깨끗했다. 기준 커밋은 `2594b18`이었다.
- 최초 기본 Python 테스트 실행은 89개 수집 항목 중 88개 통과, 1개 import 오류였다. `test_upload_notion_notes.py`가 선택적 toolkit의 `httpx`를 요구했다. 기존 uploader가 사용하는 `../notion-native-toolkit/.venv/bin/python`에서 이 의존성과 모듈 import를 확인했고, 최종 전체 검증에 그 환경을 사용했다. 의존성을 새로 설치하지 않았다.
- 운영 메타데이터에서는 오디오 82개 모두 대응 전사와 회의록이 있었고, 빈 파일은 없었다. 전체 회의록은 119개였다. 파일 존재는 내용 정확도나 게시 준비 완료를 뜻하지 않는다.
- 로컬 Voice Memos LaunchAgent는 등록되어 있었으며 조회 시 실행 중이 아니었고 마지막 종료 코드는 0이었다. 이는 과거 실행의 종료 신호이며 이번 변경의 실제 녹음 E2E 증거로 사용하지 않았다.
- 기존 실험에는 합성 화자 할당 비교, VAD clip 처리, 본문을 제외한 실험 보고서 검증이 있었다. 이 코드를 재사용해 실험의 기본 검증이 실행 가능한지 확인했다.

### 재사용과 변경 파일

새 의존성 없이 기존 `validate_meeting_note`, `render_files`, `enqueue`, `sha256_file`, JSON 원자적 쓰기와 Python 표준 라이브러리를 사용했다. 기존 셸 진입점은 오디오 수집·교정·잠금을 맡고, 새 `sh/complete_local_notes.py`가 회의록 이후의 상태와 재시도를 맡는다.

- 오디오 보존: `sh/sync-voice-memos.sh`, `sh/prepare-audio-queue.py`, `sh/format_transcript.py`
- 회의록·복구: `sh/make-notes.sh`, `sh/run-local-pipeline.sh`, `sh/complete_local_notes.py`
- 게시 검증: `sh/notion_publication.py`, `sh/run-notion-publication-pipeline.sh`, `sh/run-notion-publish-agent.sh`
- 설치 템플릿: `sh/notion-publication-launchd.sh`의 기본 모드를 로컬 `--prepare`로 변경했다. 등록된 스케줄러는 수정하지 않았다.
- 문서: `README.md`, `docs/NOTION_PUBLICATION_PIPELINE.md`, 이 평가 기록
- 테스트: `tests/test_notion_publication.py` 확장 및 오디오·전사·회의록·단계 복구 회귀 테스트 파일 5개 추가

README의 제한된 실험을 전체 ASR의 우열로 일반화하던 문구도 적용 범위를 명시하도록 수정했다. 기존 실험 기록 자체는 변경하지 않았다.

### 남은 한계와 후속 판단

1. **실제 품질과 성능은 미측정**: 이번에는 실제 회의를 재전사하거나 LLM을 호출하지 않았다. 사람 정답이 있는 대표 표본과 허용 기준이 없으므로 WER/CER, 화자 오류, 숫자·부정어·액션의 사실 보존, 지연시간·비용 개선을 주장하지 않는다. 다음 품질 평가에는 승인된 표본과 사람 검토가 필요하다. 기존 shadow 실험 경로를 사용할 수 있다.
2. **외부 E2E 미실행**: 실제 reviewer의 WDC/전략 자료 조회, Notion 생성·수정·fresh fetch, CI·배포를 실행하지 않았다. 합성 테스트 통과는 이 연결들의 성공을 뜻하지 않는다.
3. **기존 데이터의 소급 복구 없음**: 과거 전사·노트·큐를 일괄 재처리하지 않았다. 기존 준비 기록이 없는 큐 항목은 게시 준비에서 거절될 수 있으며, 의도한 회의를 지정해 재검토해야 한다. 새 source map 이전의 모호한 녹음 충돌은 누락 대신 별도 사본으로 보존되므로 기존 중복 여부 확인이 필요할 수 있다.
4. **운영 설치 상태 보존**: 커밋·푸시, 자격증명 변경, LaunchAgent 재설치·시작·종료는 하지 않았다. 기존 게시 LaunchAgent가 `--publish`만 실행한다면 새 승인 검사를 통과하지 못한다. 실제 운영 모드 변경은 별도 작업이다.
5. **보장 범위**: 이번 내구성 테스트는 프로세스·단계 실패와 재시도를 다룬다. 전원 손실에 대한 다중 파일 트랜잭션, 외부 API의 정확히 한 번 실행, 모든 과거 산출물의 의미 정확도를 보장하지 않는다. legacy 원격 오케스트레이터는 별도 경로로 남아 있으며 새 로컬 상태 복구 보장을 적용하지 않았다.

### 종료 조건

문서·코드 평가, 재현 가능한 필수 로컬 결함 수정, 기존 및 추가 회귀 테스트, 통합 검증, 운영 한계 기록을 완료했다. 이번 목표는 완료이며 승인 없이 남은 외부 작업을 실행하지 않는다.
