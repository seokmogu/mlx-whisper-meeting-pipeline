# 회의록 한국어 자연스러움 규칙

이 규칙은 `humanize-korean` quick rules v2.0 가운데 회의록 초안에 맞는 항목만 적용한다. 후처리 윤문이 아니라 최초 작성 단계에서 사용한다.

## 보호 대상

다음 내용은 문체를 이유로 바꾸지 않는다.

- 결정의 확정성, 부정, 조건, 수치, 날짜, 금액, 고유명사, 직접 인용
- `A#`, `M#`, `§4.x` ID와 H1/H2/H3 구조
- Action Items의 담당 범위·기한·근거
- `확정`, `방향 합의`, `확인 필요`, `AI 추정` 같은 운영 상태
- `### 5.2 검증 완료`의 원문→정정 쌍과 `### 5.3 검증 필요`의 literal fragment
- API, LLM, MCP, Skill, Notion, Slack, GitLab처럼 통용되는 기술 용어

구조화 불릿과 필요한 볼드는 회의록 장르의 인터페이스이므로 `humanize-korean`의 C-2와 J-1을 적용하지 않는다.

참석자 부록도 구조화 데이터다. 같은 `사용자 확정 참석자`, `직원 디렉토리에서 active로 확인됨`, roster 근거를 사람마다 반복하지 말고 한 줄로 합친다. 동명이인 해소처럼 사람별 근거가 실제로 필요할 때만 예외로 둔다.

## 작성 규칙

### 구체적인 주어와 동사

- `언급됐다`, `제기됐다`, `논의됐다`, `설명했다`를 기본 종결어처럼 반복하지 않는다. 발화 근거가 있으면 `요청했다`, `지적했다`, `제안했다`, `확인했다`, `공유했다`, `반박했다`, `남겼다`처럼 실제 행위에 맞는 동사를 쓴다.
- 화자를 확정할 수 없으면 억지 주어를 만들지 않는다. 그 경우에도 같은 피동 종결을 네 문장 이상 연속해서 쓰지 않는다.
- `~에 대해 논의했다`보다 `~를 논의했다`, `~를 통해`보다 문맥에 맞는 직접 동사를 우선한다. `가지고 있다`, 이중 피동, 추상 주어와 만능 동사를 피한다. (A-1, A-7~A-10, A-15)

### 영문 병기와 기술 용어

- 한글명과 영문 약어·이름의 병기는 문서 본문 첫 등장에만 사용한다. 이후에는 한글명 또는 정해진 짧은 이름만 쓴다. 예: 첫 등장 `니카(Nika)`, 이후 `니카`. (B-1)
- 검증 부록의 정정 표기와 사람의 소속 표기는 이 제한에서 제외한다.
- 업계 표준 영문 용어는 억지로 번역하지 않는다. 광고성 영어만 쉬운 한국어로 바꾼다. (B-2)

### 문장 리듬과 명사화

- 상세 논의의 인접 불릿 네 개가 같은 종결어미로 끝나지 않게 한다. 다만 사실 상태를 바꾸려고 동사를 임의로 꾸미지 않는다. (E-2)
- `~할 수 있다`를 가능성 표시가 필요하지 않은 곳에서 반복하지 않는다. 확정된 기능이나 방향은 직접 서술한다. (A-10)
- `방향성`, `가능성`, `필요성`, `정합성` 같은 추상 명사와 `~적`, `~화`가 겹치면 동사나 구체 명사로 풀어 쓴다. (F-4, F-5)
- 긴 관형절이 겹치면 두 문장으로 나눈다. 내용 앵커는 삭제하거나 동의어로 바꾸지 않는다. (A-18)

### AI 관용구와 완곡 표현

- `결론적으로`, `따라서`, `이를 통해`, `요약하면`, `다음과 같은` 같은 도입·결산 문구를 반복하지 않는다. 바로 사실이나 판단을 쓴다. (D-1~D-3)
- `시사하는 바가 크다`, `주목할 만하다`, `혁신적` 같은 과장 표현을 만들지 않는다. (D-2, D-4)
- `~로 보인다`, `~로 판단된다`, `가능성이 있을 수 있다` 같은 완곡을 겹치지 않는다. 불확실하면 `확인 필요`로 명시한다. (G-1, G-2)
- 문두의 `또한`, `따라서`, `즉`, `나아가`, `이 관점에서`를 반복하지 않는다. (H-1, H-3, H-4)
- `~한 것이다`, `~다는 것이다`, `~할 필요가 있다`가 이어지면 직접 서술로 바꾼다. (I-1, I-3, I-4)

## 출력 전 자체 점검

1. 수치·날짜·이름·제품명·직접 인용·부정·조건이 입력과 일치하는가.
2. 본문에서 같은 한글+영문 병기가 세 번 이상 반복되지 않는가.
3. 상세 논의에서 같은 보고 동사가 네 불릿 이상 연속되지 않는가.
4. `언급됐다/설명했다/제기됐다/논의됐다`가 상세 논의의 기본 종결어가 되지 않았는가.
5. 구조와 상태 라벨을 보존하면서도 문장 자체는 자연스러운가.
6. 자연스럽게 보이려고 입력에 없는 주어, 인과, 평가, 비유를 추가하지 않았는가.

위 조건을 만족하지 못하면 초안 단계에서 고친 뒤 전체 회의록을 출력한다. 별도의 광범위한 2차 윤문으로 사실을 흔들지 않는다.
